# PaperS3 儿童 EDC 日程机设计文档

**Date:** 2026-03-20
**Repo:** `BinFontLib`
**Branch:** `papers3-binfont-demo`

## 目标

基于 M5Stack PaperS3 开发一个面向小学生的电子纸 EDC 工具。第一阶段不是通用待办应用，而是一个克制、安静、中文排版优先的“日课执行器”：家长通过微信小程序布置当天任务，孩子在 PaperS3 上查看和完成任务，设备负责低干扰展示、即时反馈、积分累计与离线可用。

## 产品定位

- 面向对象：小学生 + 家长
- 设备角色：PaperS3 日程机 / 日课本
- 家长端角色：微信小程序后台，用于布置任务、查看统计、补充照片记录
- 云端角色：任务下发、完成记录接收、积分累计、设备配置同步

这不是普通的 Todo List，也不是卡通成长 App。设备端要像一本高级、克制、可反复翻看的电子日课页。

## 架构约束

为保证后续可持续优化电子纸显示效果，渲染层必须与业务层保持明确边界。

- `render` 相关逻辑应尽量独立，负责版式绘制、区域刷新、状态栏绘制、任务行绘制、屏保插图等纯显示能力
- `font` 管理相关逻辑应尽量独立，负责字体加载、字体切换、中文排版度量、字形缓存和后续渲染策略优化
- 业务层只描述“当前要显示什么状态和数据”，不直接散落控制具体绘制细节
- 后续若要优化刷新效果、条带更新、灰阶策略、字距或版式算法，应尽量集中在渲染与字体模块内部完成，避免在业务页面代码中到处修改

目标是让未来的显示优化、字体替换、刷新策略迭代，尽可能不影响任务逻辑、积分逻辑、同步逻辑和设备配置逻辑。


### 1. 电子纸优先
- 充分考虑 PaperS3 刷新特性、对比度和残影控制
- 避免高频抖动式交互和杂乱层叠界面
- 重要反馈明确，但不喧闹

### 2. 中文排版优先
- 字体层级比图标层级更重要
- 依靠字重、字号、行距、留白建立层次
- 页面像纸面，不像手机 App

### 3. 高级的学生日课本气质
- 矩形、细线、秩序感、留白
- 不使用圆形 checkbox、卡通图标、泡泡标签、俗套待办样式
- 完成态采用矩形标记与整行状态变化

### 4. 低干扰但有成长反馈
- 孩子完成任务后即时记分
- 通过贡献图和积分强化持续感
- 但不引入过强游戏化机制

## 三端结构

### PaperS3 设备端
负责：
- 展示当天任务
- 支持选中、确认完成、即时计分
- 显示状态栏、屏保页、进展页
- 本地缓存任务与待同步记录
- 提供设备配置入口与 Wi‑Fi 输入

### 家长微信小程序
负责：
- 配置当天任务
- 查看任务完成情况
- 查看积分和贡献图统计
- 支持拍照上传记录

### 云端服务
负责：
- 保存任务与排序
- 保存完成记录与积分累计
- 为设备提供同步接口
- 为小程序提供查询与配置接口

## 第一阶段闭环

1. 家长在小程序布置任务
2. PaperS3 开机或定时唤醒后同步今日任务
3. 孩子在设备上查看今天的任务
4. 点击任务行或左侧矩形标记进入确认
5. 确认完成后立即更新任务状态、积分与本地记录
6. 设备联网时自动将完成记录同步到云端
7. 家长在小程序查看当天完成情况、贡献图和积分统计
8. 设备休眠后停留在优雅屏保页

## 任务模型

第一阶段任务保持简单，围绕“纯文字任务”设计。

### 建议字段
- `task_id`
- `date`
- `title`
- `status`
- `points`
- `sort_order`
- `created_by`
- `completed_at`

### 状态
- `未完成`
- `待确认`
- `已完成`

### 规则
- 任务以文字内容为主，不引入复杂时间段或子任务结构
- 任务顺序由家长在小程序中配置，并同步到设备
- 孩子在设备上完成任务后立即生效，不需要家长审核

## 积分与贡献图

### 积分
- 每个任务具备固定积分值
- 完成即加分
- 第一阶段只做基础累计：今日积分、累计积分、本周积分、连续完成天数
- 暂不引入复杂倍率、抽奖或商城逻辑

### 贡献图
采用类似 GitHub contribution 的矩形热力图，但更适合儿童成长记录和电子纸显示。

- 单元格为矩形
- 以灰度深浅表示当天完成度
- 设备端只显示摘要
- 小程序端显示完整视图

建议四档：
- 0：无完成
- 1：完成少量
- 2：完成过半
- 3：全部完成

## 设备端页面结构

第一阶段设备端只做 5 个核心页面。

### 1. 主屏 / 今日页
结构：
- 顶部状态栏：电量、今日任务总数、已完成数
- 中上部：日期信息，但不喧宾夺主
- 主体：今日任务列表
- 底部提示区：同步状态、积分变化或轻提示

这是整个产品的核心页，设计目标是“打开就是今天该做什么”。

### 2. 完成确认页
- 由任务行或左侧矩形完成标记触发
- 只做一件事：确认完成
- 完成后返回主屏并更新状态

### 3. 积分 / 进展页
- 显示当前总积分
- 显示近期贡献图摘要
- 显示连续完成信息

### 4. 屏保页
- 休眠或静置后停留
- 核心信息：当天日期 + 今日任务概览
- 任务多时自动降级为“任务总数 + 完成情况”
- 可以加入 Notion 风格细线插图，作为气质辅助而非主视觉

### 5. 设备配置页
- Wi‑Fi 配置
- 同步状态
- 手动同步入口
- 设备标识 / 绑定状态摘要

## 主屏与屏保的排版原则

### 主屏
- 任务优先，日期次之
- 每条任务是规整横向信息带
- 左侧是矩形完成标记，中间是中文任务文本，右侧是轻量状态信息
- 如果内容太多，不强塞，而是做版式降级

### 屏保
- 像一张安静的今日纸面
- 上部为日期
- 中部为“今日安排”或类似标题
- 下部展示任务摘要或任务总览
- 可加入少量细线几何插图或学习相关线描元素

## 视觉语言

### 必须坚持
- 矩形
- 细线
- 低装饰
- 中文字体主导层次
- 留白和秩序感

### 必须避免
- 圆形 checkbox
- 圆角泡泡按钮
- 俗气卡片堆叠
- 过多图标化表达
- 卡通贴纸感视觉

## 完成交互

### 用户操作
- 点击任务整行，可进入待确认状态
- 也支持点击左侧矩形完成标记
- 最终都需要确认完成，避免误触

### 反馈
- 完成即生效
- 立即更新任务完成状态
- 立即增加积分
- 记录写入本地待同步队列

## 同步机制

第一阶段使用轻同步策略，不做长连接。

### 同步时机
- 开机同步一次
- 定时唤醒同步一次
- 用户手动触发同步一次

### 下发内容
- 今日任务
- 任务排序
- 任务积分
- 基础设备配置状态

### 上报内容
- 完成记录
- 完成时间
- 积分变化
- 设备状态摘要

## 离线策略

设备必须离线可用。

- 最近一次同步的今日任务保存在本地
- 无网络时仍可完成任务
- 完成动作先写入本地待同步队列
- 联网后补传
- 冲突处理以“已完成优先”为第一阶段原则，避免回滚孩子已完成的任务

## Wi‑Fi 配置方案

用户确认采用设备端输入，而不是配网页或蓝牙配网。

### 配置入口
- 设备主界面中有设备配置入口
- 平时不打扰主流程
- 未联网时可在状态栏中给出轻提示

### 配置流程
1. 进入设备配置
2. 扫描附近 Wi‑Fi 列表
3. 选择 SSID
4. 跳转密码输入页
5. 输入密码并测试连接
6. 保存配置并返回

### 输入页风格
- 像纸面表单而不是手机输入法
- 矩形键盘区，网格排列
- 支持字母、数字、退格、大小写切换、确认
- 尽量减少击键次数

## MVP 范围

### 设备端
- 今日任务主屏
- 任务选中与确认完成
- 屏保页
- 状态栏
- 积分 / 贡献图摘要页
- 设备配置页
- Wi‑Fi 扫描与密码输入
- 本地缓存与同步

### 小程序
- 配置今日任务
- 查看任务完成情况
- 查看积分与贡献图
- 补充照片记录

### 云端
- 任务下发
- 完成记录接收
- 积分累计
- 基础设备识别 / 绑定

## 暂不纳入第一阶段

- 阅读器
- 多孩子复杂账号体系
- 家长审核完成结果
- 强游戏化动画系统
- 奖励商城
- 蓝牙配网
- 复杂通知系统

## 推荐开发顺序

### 阶段 1：设备纯本地版
- 用本地假数据完成主屏、确认页、屏保页、配置页
- 优先打磨 PaperS3 上的排版与交互

### 阶段 2：设备本地持久化
- 缓存任务
- 保存完成记录
- 保存积分累计

### 阶段 3：云同步 API
- 拉取任务
- 上报完成记录
- 同步积分

### 阶段 4：家长微信小程序
- 配任务
- 看统计
- 看贡献图
- 上传照片

### 阶段 5：体验打磨
- 屏保线条插图
- 版式优化
- 刷新策略优化
- 电量与唤醒策略优化

## 结论

这个产品第一阶段的核心不是“功能多”，而是“设备端观感正确、交互节奏正确、闭环可运行”。

最重要的价值点是：
- 孩子每天愿意看
- 家长每天愿意用
- 设备像一本真实可用的电子日课本
- 即使网络不稳定，产品依然可靠
